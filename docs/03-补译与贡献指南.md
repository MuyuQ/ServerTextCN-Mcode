# 03 · 补译与贡献指南

插件显示英文 = 这句还没进词典。这一页讲怎么把漏译变成新词条：**只想报告**的看[路径 A](#路径-a只报告：把现场交给维护者)，**想自己动手**的看[路径 B](#路径-b自己补：ai-辅助回填本地词典)，**想贡献回项目**的看[路径 C](#路径-c提交回项目仓库)。

---

## 路径 A：只报告：把现场交给维护者

1. 进游戏复现那句话（重新和 NPC 对话、再进一次战场都行）。开着默认的漏译收集，它已被自动记录。
2. `/stcn show` → 对应功能页 → 在"未汉化记录"里**点选那条记录**。
3. 点击 **复制反馈** → 文字已被自动全选 → **Ctrl+C**。
4. 到项目仓库提一个 **Issue**，标题写 `[漏译] 原文摘要`，正文直接粘贴。

反馈自带 NPC、地点、来源、时间、词典版本等现场信息，维护者可以直接定位。误译报告同理：切到"查看汉化记录"，选中译文有问题的那条，同样复制。

> 手动整理反馈至少要包含：**完整英文原文**（一字不差，含标点）、出现的窗口类型（问候/菜单/训练师/战场/系统公告）、NPC 名字（如有）。缺了原文的反馈无法处理。

## 路径 B：自己补：AI 辅助回填本地词典

适合"等不及更新、想立刻自用"的情况。流程：**备份 → 把词典+漏译记录交给 AI → 核对 → 替换文件 → 验证**。

### B1. 准备材料

把以下内容打包给 AI（少则一个记事本贴文，多则一个压缩包）：

| 材料 | 在哪 |
|---|---|
| 漏译反馈文本 | 游戏内"复制反馈"，或存档 `WTF\Account\<账号>\SavedVariables\ServerTextCN_Mcode.lua` 里的 `McodeSTCN_DB.misses`（窗口）/ `McodeSTCN_DB.announcements.misses`（公告） |
| 窗口词典 | 插件目录 `ServerTextCN_Mcode_Data.lua` |
| 匹配代码 | 插件目录 `Core.lua`、`Window.lua`、`Templates.lua`、`.toc` |
| 公告词典与代码（补公告才需要） | 插件目录 `AnnouncementRules.lua`、`Announcements.lua` |
| 操作要求 | 插件目录《使用说明-3.1.md》（内含完整 AI 提示词） |

### B2. 使用现成提示词

《使用说明-3.1.md》的"复制以下提示词给 AI"一节有一段完整的提示词，覆盖翻译口径（忠实原文、保留否定与数字、不编造）、回填位置（GREET/MENU/公告规则）、版本号要求、语法检查和交付格式。**整段复制**，和材料一起发给 AI 即可。

### B3. 核对与安装

1. **核对词典版本**：AI 交付的 `ServerTextCN_Mcode_Data.lua` 文件头 `McodeSTCN_DictionaryInfo.version` 必须比旧值新（格式 `年.月.日.修订号`），公告改动则核对 `AnnouncementRules.lua` 的 `dictionaryVersion`。只回填内容不改版本号 = 交付未完成，退回重做。
2. **核对内容**：抽查几条"原文 → 译文"，确认没有把语境翻错、没有丢否定词。
3. **安装**：完全退出游戏（安全起见），用新文件替换插件目录里的同名文件（安装前备份原文件到 AddOns **外**）。
4. **验证**：进游戏 `/reload`（或重启客户端），重访同一个 NPC / 再触发同一条公告，确认显示中文且占位符（角色名、职业等）展开正确。原漏译要**实际命中一次**后才会从未汉化列表里移出。
5. **回滚**：不对劲就退出游戏，把备份文件放回去。词典回填不需要动存档。

### B4. 记得顺手贡献

自用回填的词条往往就是别人的漏译。按路径 C 提交回仓库，一次劳动大家受益。

## 路径 C：提交回项目仓库

### 窗口词典词条

**少量词条**：直接编辑 `ServerTextCN_Mcode/ServerTextCN_Mcode_Data.lua`，在 `McodeSTCN_Data.GREET`（问候语）或 `McodeSTCN_Data.MENU`（菜单选项）表里加一行：

```lua
["What can I do for you, $N?"] = "我能为你做点什么，$N？",
```

**键（英文）的规则**——必须是服务器实发原文，遵守与插件相同的归一化口径：

- 颜色代码（`|cffxxxxxx…|r`）不写入键，存干净文本；
- 键里的 `$B`/`$b` 折叠成空格；连续 4 个以上的句点折叠成标准省略号 `...`；连续空白折叠成一个空格；
- 原文里自带 `$n`、`$C`、`$g男:女;` 等占位符的，**原样保留**；不要把实发文本里已展开的角色名硬改成 `$n`（插件运行时会自己尝试还原，只有证据充分时才用占位符键）；
- 同一句在不同 NPC 处含义不同时，不要强行收录成全局词条，先在 Issue 里讨论。

**值（中文）的规则**：

- 用符合巫妖王之怒语境的简体中文，忠实原文：保留人物、阵营、动作、条件、**否定**、数字，不加原文没有的信息；
- 译文里可以保留占位符，显示时插件会按你的角色信息展开：`$n`/`$N`（角色名）、`$c`/`$C`（职业，小/大写）、`$r`/`$R`（种族）、`$g男词:女词;`（按性别二选一）、`$B`（换行）；
- 例：`"你好，$N！欢迎来到$g兄弟:姐妹;会。"`。

**技术要求**：文件必须保持 **UTF-8（无 BOM）**；Lua 字符串内 `"` 写成 `\"`、`\` 写成 `\\`；新条目按英文键的字母序插入（整个表保持有序）；**同一键不能出现两次**。

**批量补词条用工具**（推荐，自动处理排序、冲突、转义和版本头）：

```bash
# 第 1 列英文、第 2 列中文，制表符分隔；# 开头的行是注释
# 可选第 3 列：greet（只进问候）/ menu（只进菜单）/ both（默认，两边都进）

python tools/add_dictionary_entries.py 词条.tsv            # 演练模式：只报告会加什么，不写文件
python tools/add_dictionary_entries.py 词条.tsv --write    # 实际写入（自动生成 .bak 备份）
```

> 不确定 TSV 怎么写？复制 `tools/sample_entries.tsv`，照着里面的注释替换成你的词条即可。用 Excel 编辑容易把编码存坏，建议用 VS Code / Notepad++。

工具会自动：按词典口径归一化键、跳过重复与冲突（同键不同译文默认不覆盖，`--force` 才覆盖）、按字母序插入、更新文件头的词典版本号与 `contentHash`。写完把输出的变更清单贴进 PR 即可。

### 公告与战场规则

公告**不进** `Data.lua`，在 `ServerTextCN_Mcode/AnnouncementRules.lua` 里按固定格式添加：

```lua
add("规则ID", "规则名",
    "^服务器实发句式的正则表达式$",
    "用于说明的英文模板 {占位名}",
    "中文译文 {占位名}。",
    "一条真实抓到的实发原文样例",
    function(捕获组1, 捕获组2) return { ["占位名"] = 捕获组1 } end,
    "来源")   -- bg=战场 / system=系统通知；战斗规则可省略此参数
```

要求：正则锚定整句（`^…$`，句尾标点要考虑服务器实发是 `!` 还是 `.`）；捕获的阵营/据点词必须在既有词典表里能查到；译文占位符与 `add` 支持的标记（`{玩家名}`、`{阵营}`、`{据点}`、`{战场}`、`{数字}`、`{文本}`、`{职业}`、`{种族}`）一致；**每条规则必须附一条实发样例**；同时更新文件顶部 `dictionaryVersion`。动态内容复杂、当前框架吃不准的，先开 Issue 附原文讨论，不要写成会大面积误命中的宽松正则。

### Pull Request 检查清单

提交前逐项确认：

- [ ] 只改了与本次补译有关的文件（词条、规则、版本号），没有顺手重排/清空词典；
- [ ] 新增键与既有键无重复、无忽略大小写后的冲突；有同键不同译的取舍已说明；
- [ ] 词典版本号已按规则递增（`年.月.日.修订号`，同日 `.2`、`.3`…，跨日新日期 `.1`），窗口词典 `contentHash` 已重算（用工具或按《使用说明-3.1.md》的口径）；
- [ ] 公告改动同步更新了 `dictionaryVersion`；未改动的词典保持原版本号；
- [ ] 文件仍是 UTF-8（无 BOM）、Lua 5.1 语法可解析（可用仓库维护者的 `lua_check` 流程，或至少在游戏里加载无报错）；
- [ ] 已在游戏里 `/reload` 实测：重访对应 NPC / 重触发对应公告，显示正确、占位符展开正确；
- [ ] PR 描述里写了：补译数量、原文出处（漏译反馈文本）、验证步骤、词典版本"旧 → 新"。

AI 辅助翻译与模拟检查都不能代替真实游戏验收——自己进游戏看过一遍再提交。
